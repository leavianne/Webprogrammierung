2. Testen Sie für beide URLs auch die curl-Schalter -L und -I aus. Erklären Sie die
Unterschiede bzw. Änderungen in den Ausgaben zu den originalen Abfragen in a.
und b.!

- Schalter -I (Head-Request):
	- Sendet Methode HEAD statt GET.
	- Der Server liefert nur die Header-Informationen (Metadaten), kein Body/HTML-Inhalt wird übertragen. spart Bandbreite.
- Schalter -L (Location-Follow):
	- Folgt automatischen Weiterleitungen (Redirects wie Status 301/302).
	- curl führt bei einer "Location"-Antwort automatisch eine neue Anfrage an die Ziel-URL aus, bis das finale Dokument (z.B. 200 OK) erreicht ist.

3. Testen Sie für beide URLs auch den curl-Schalter --http2 aus. Was bedeutet im
Response h2c?

- Schalter --http2: Erzwingt den Versuch, HTTP/2 zu nutzen.
- Bedeutung "h2c": Steht für "HTTP/2 Cleartext".
- Interpretation: HTTP/2 über eine unverschlüsselte TCP-Verbindung (ohne TLS). Wird von den meisten modernen Browsern aus Sicherheitsgründen nicht unterstützt, curl kann es jedoch via Upgrade-Header anfragen.

1. Wie unterscheidet sich die Anzahl der Verbindungen und damit das zeitliche
Beziehen der Objekte über die Verbindungen z. B. nacheinander/parallel (pro
Domäne bzw. Zieladresse)?

- HTTP (Tab 1, HTTP/1.1): Viele parallele TCP-Verbindungen (Browser-Limit meist max. 6 pro Domäne). Objekte blockieren sich gegenseitig (Head-of-Line Blocking), Laden erfolgt gestaffelt/nacheinander in "Wellen".
- HTTPS (Tab 2, HTTP/2): Nur eine einzige TCP-Verbindung (Multiplexing). Alle Objekte werden parallel und gleichzeitig über diesen einen Kanal gestreamt. Deutlich schnellerer Gesamt-Ladevorgang.

2. Berechnen und vergleichen Sie die TFFB3 (Time To First Byte) beider Tabs für das
Dokument (wechseln der Anzeige von All bzw. Img auf -> Auswahl Doc)!

- HTTP (Tab 1): TTFB ist oft minimal kürzer beim Erstkontakt, da der TLS-Handshake (Verschlüsselung) entfällt.
- HTTPS (Tab 2): TTFB ist beim allerersten Aufruf etwas höher, da vor dem HTTP-Request erst der TCP- und der TLS-Handshake durchgeführt werden müssen.

3. Begründen Sie die Unterschiede in den Content Download-Zeiten beider Anfragen
(Auswahl Doc)!

- Bei HTTP/1.1 müssen Ressourcen oft warten, bis eine TCP-Verbindung frei wird (Warteschlange).
- Bei HTTP/2 entfällt die Wartezeit auf freie Sockets. Obwohl die reine Übertragungszeit der Bytes ähnlich ist, verringert HTTP/2 die Latenz durch das Senden aller Anfragen in einem Rutsch drastisch, was den Content Download effizienter verschachtelt.
